# Security pass — Phase E §9

**Date:** 2026-08-11 · Read-only review; nothing was changed. **Scope:** code added today — the uploads/candidates/issue-quote/health routes, `src/uploads`, `src/storage`, `src/parsing`, `src/enrichment`, `src/shared-layer`, `src/quote`, migrations 0020–0024.

**Read the reachability tag on every finding. [live]** = reachable today by an HTTP request. **[latent]** = the defect is real but nothing calls the code yet, or reaching it needs a second vulnerability. Verified by grep: `src/parsing/**` and `src/enrichment/crawl.ts` have **no callers outside their own tests**, and the app's only SQL surface is parameterised function calls — so "a logged-in member runs arbitrary SQL" is not a capability anyone currently has. Latent findings still matter: the migrations state that the database is the enforcement, so a DB layer that holds only because the app happens to call it correctly is a broken premise even when unexploitable.

## HIGH

**H1 [live] · The agency's floor prices are served to every quote recipient.** `src/app/q/[token]/page.tsx:73` passes `rehydrateQuote(resolved)` as a prop to `<QuoteDocument>`, which is `'use client'` (`quote-document.tsx:1`), so Next serialises the whole object into the RSC payload embedded in the HTML. It carries `lines[].floorPrice` — the D8 hard floor, the lowest number the agency will ever accept (`src/engine/pricing.ts:48`, persisted at `src/quote/issue.ts:159`) — plus `trace.steps[].rule` with tier thresholds. **Attack:** open `/q/{token}`, view source, search `floorPrice`; the customer now knows the bottom of the negotiating range on every line, the one number the guardrail model exists to protect. `db/migrations/0022:152-154` promises the exact opposite ("no cost or margin figure"). *Fix: strip `floorPrice` and the step-3 `rule` in `rehydrateQuote`, or project a customer-safe line shape before the prop crosses to the client.*

**H2 [live] · Quote-link revocation is structurally impossible.** `src/quote/issue.ts:246-255` revokes by updating `token_hash` on `quote_versions`, but that write is blocked twice: `0002_rls.sql:136` drops the UPDATE policy under `force row level security`, and `0003:88-92` installs `quote_versions_immutable`, an unconditional `before update or delete` trigger. Zero rows match, `reissueQuoteLink` returns null, and the route answers `404 not_found` (`src/app/api/inquiries/[id]/quote/route.ts:99`). **Attack scenario:** an owner emails a quote to the wrong address; the "replace link" button tells him the quote does not exist and the leaked bearer token stays valid. *Fix: add `revoked_at` to `quote_versions` with its own UPDATE policy and revoke by setting it, rather than mutating an immutable row.*

**H3 [live] · Quote tokens never expire and have no revocation predicate.** `resolve_quote_link` (`0022:198-201`) filters only on `token_hash` and `q.state <> 'draft'` — no `valid_until`, no `revoked_at`, unlike `0011:286` which does check `revoked_at is null` for request links. With H2 this makes a quote link a permanent, unrevocable bearer credential. *Fix: add `and qv.valid_until >= current_date` and `and qv.revoked_at is null`.*

**H4 [latent] · `allocate_quote_number` is SECURITY DEFINER, takes the tenant id as a parameter, and never checks membership.** `0003:32-58`. It has no explicit GRANT, so PostgreSQL's default `EXECUTE TO PUBLIC` applies. Anyone able to issue SQL as `app_user` calls `select public.allocate_quote_number('<victim-uuid>')` in a loop: each call permanently increments that tenant's gapless per-year counter — a §14 UStG gap that cannot be repaired — and the return value discloses how many quotes the competitor has issued this year. Pre-existing, but `0022:104` is what puts it in the live quote path. *Fix: `if not public.is_agency_member(target_agency) then raise exception …`, plus `revoke execute … from public`.*

**H5 [latent] · `allocate_quote_number` is shadowable via `pg_temp`.** Same function: `set search_path = public` (`0003:36`) with **unqualified** `quote_number_counters` at `:42`, `:49` and `:53`. That setting does not remove `pg_temp`, which Postgres searches first for relations, and `TEMP` is granted to PUBLIC by default. A session that creates a temp table of that name with a `BEFORE INSERT` trigger gets the trigger body executed inside the definer context — per `db/dev-setup.sh:43-46`, the database owner. This is the exact failure `0006:80-82` and `0011:254-256` document and defend against with `set search_path = ''`. Needs an existing SQL-injection or direct DB access; none was found. *Fix: `set search_path = ''` and qualify all three references.*

**H6 [latent] · A ~120 KB .xlsx exhausts the Node heap.** `src/parsing/xlsx.ts:379-382` and `:405-407` bound rows (200,000) and columns (4,096) **independently, never their product**, and `place()` at `:369` does `while (row.length <= cell.column) row.push('')`. **Attack:** 200,000 rows of `<row r="N"><c r="FAA1"/></row>` — ~6 MB of repetitive XML deflating to roughly 120 KB, inside both the 25 MB upload cap and the 64 MiB per-entry ZIP cap — materialises ~819 M empty strings, about 6.5 GB. Process death, not a caught error. The ZIP layer's own three bounds are correct (see CLEAN); this gap sits one layer above them. *Fix: a `maxCells` budget decremented as cells are placed.*

**H7 [latent] · The crawler has no SSRF guard of any kind.** `src/enrichment/urls.ts:142-150` validates only the scheme and that a host exists; `src/enrichment/crawl.ts:498-503` then fetches with `redirect: 'follow'`. Neither file mentions loopback, RFC1918, link-local, CGNAT, IPv6 ULA or `::ffff:` addresses. Three ways in: (a) the prospect's website field is attacker-supplied, so `http://169.254.169.254/latest/meta-data/…` passes — and the same-host check at `:755` derives `options.host` from that very URL, so it returns true and guards nothing; (b) `options.host` may be null, which `:663` documents as disabling the check; (c) a legitimate host can 302 into the metadata service — redirects are followed inside undici, the host check is never re-applied per hop, and `finalUrl` (`:516`) is computed only after the body is read. No DNS pinning, so rebinding works regardless. The fetched text is stored in `crawl_cache.text_excerpt` and handed back for extraction, making this exfiltration rather than a blind fetch. *Fix: resolve the host, reject non-public IPs, pin the resolved address for the connection, and use `redirect: 'manual'` with per-hop revalidation.*

## MEDIUM

**M1 [live] · Unbounded body buffering before the size check.** `src/app/api/uploads/[id]/chunks/route.ts:37` does `await request.arrayBuffer()` fully into heap; the `> CHUNK_BYTES` guard is at `:44`, after. App Router handlers have no default body cap (`api.bodyParser.sizeLimit` is Pages Router only) and `next.config.ts` sets `output: 'standalone'`, so a self-hosted container has no upstream 4.5 MB limit either. One authenticated session PUTs a multi-GB body and OOMs the process. *Fix: reject on `Content-Length` before reading; cap while streaming.*

**M2 [live] · Failed uploads leak their chunks, and there is no upload quota anywhere.** `src/uploads/jobs.ts:276-296` — both the length-mismatch and digest-mismatch paths call `failJob` and return with the `bytea` rows intact; the `delete from upload_chunks` at `:307` is on the success path only. `sha256` is client-supplied and is the uniqueness key (`on conflict (agency_id, sha256)`), so varying it mints unlimited jobs, each parking up to 26 MiB in Postgres. Nothing reaps orphans, nothing caps concurrent jobs, and the upload routes have no rate limit — unlike `src/auth/throttle.ts` and `src/chat/rate-limit.ts`. *Fix: delete chunks inside `failJob`; add a per-agency in-flight cap.*

**M3 [live] · Owner-only catalogue writes are enforced in the route only, not in SQL.** `src/app/api/candidates/route.ts:30-32` checks `agency.role !== 'owner'` and comments "The database says so too — this is the early, friendlier half of the same rule." It does not: `confirm_candidate` (`0024:196-204`), `reject_candidate` (`:282`) and `confirm_candidates_bulk` (`:339`) are `security invoker` and require only an authenticated user plus RLS agency **membership**; there is no role predicate in the file. Any non-owner teammate reaching these through a future route or a script writes straight into `catalog_items`, against D11. Relatedly `0024:167-171` grants members a plain UPDATE policy on `catalogue_candidates`, and `:162-165` checks only `agency_id` on the verdict insert, so `decided_by` can name any colleague — within-tenant audit forgery. *Fix: add an owner check to all three functions and `with check (decided_by = public.current_user_id())`.*

**M4 [live] · `asAnonymous` can run on a connection carrying a previous tenant's identity.** `src/db/client.ts:98-105` takes a pooled client and runs the callback with no transaction and no identity reset. `withUser` (`:78-83`) catches, awaits `client.query('rollback')`, then releases in `finally` — if the rollback itself throws (connection reset mid-transaction), `client.release()` is called with no error argument, so node-pg returns the client to the pool rather than destroying it, with the transaction open and `app.current_user_id` still set. The next `asAnonymous` — which serves the public quote page — inherits it. Narrow trigger; silent and cross-tenant when it fires. *Fix: `client.release(true)` on the error path; wrap `asAnonymous` in a transaction that blanks the GUC.*

**M5 [latent] · `upload_chunks` rows are not bound to their parent job's tenant.** `0020:163-174` + `:300-303`: PK `(job_id, chunk_index)` with a denormalised `agency_id`, and the insert policy checks only `is_agency_member(agency_id)` — never that `job_id` belongs to that agency, and the FK does not either. A tenant knowing another's job uuid inserts `(job_id = <theirs>, agency_id = <mine>, chunk_index = 0)`; the policy passes; the victim's `record_upload_chunk` then hits `on conflict do nothing` (`:394`) and silently drops their real chunk, while RLS hides the poison row so `count(*)` never reaches `chunk_total`. The victim's upload hangs in `uploading` forever with no error anywhere. Only uuid unguessability and the absence of a raw-insert surface keep this out of HIGH. *Fix: unique index on `upload_jobs (id, agency_id)` and a composite FK from `upload_chunks`.*

**M6 [latent] · Enrichment lease ownership is not checked, contradicting the comments.** `heartbeat_enrichment_job` gets it right (`0021:549`, `and j.leased_by = p_worker`), but `charge_enrichment` (`:723`), `complete_enrichment_job` (`:583`) and `fail_enrichment_job` (`:622`) check only `and j.state = 'leased'`. After worker A's lease expires and B reclaims the row, the state is still `leased`, so A keeps charging — precisely what `:726-731` says must not happen ("one prospect's budget gets spent twice over"). A can also overwrite B's `result_json` or re-queue a job B is running. *Fix: add a `p_worker` parameter and `and j.leased_by = p_worker` to all three.*

**M7 [latent] · A cascade defeats the deliberate no-delete policy on `candidate_verdicts`.** `0024:175-179` intentionally omits a delete policy ("a training record that can be quietly removed is one that will be"), but `:101` declares `candidate_id … on delete cascade` and `:178-182` grant members delete on the parent. Deleting the candidate takes the F2.8 rejection history with it, and referential actions are not subject to the referencing table's RLS. *Fix: `on delete restrict`.*

**M8 [latent] · `record_quote_view` is an unauthenticated unbounded write into a tenant's table.** `0022:217-245` is `security definer` (so RLS on `quote_events` is bypassed) and is called via `asAnonymous`. No dedupe, no rate limit, no length bound on the two hash parameters. Anyone holding one valid quote link loops it to inflate the victim's `quote_events` without limit. Latent only because `recordQuoteView` (`src/quote/repository.ts:138`) currently has **no caller at all** — which also means the "quote view rate ≥ 80%" metric is unmeasurable today. *Fix: constrain both parameters to `^[0-9a-f]{64}$` and dedupe on `(quote_version_id, ip_hash, date)` with `on conflict do nothing`.*

## LOW

- **[latent]** `src/parsing/csv.ts:212` passes `Number.POSITIVE_INFINITY` as the row cap — xlsx bounds rows, CSV does not. A 25 MB file of newlines yields ~25 M row arrays, roughly 1.5 GB of heap.
- **[live]** `src/storage/s3.ts:85-87` inlines the raw S3 error body into the thrown `Error`. On `SignatureDoesNotMatch`, S3/R2/MinIO return `<AWSAccessKeyId>` and `<StringToSign>`, so the access key id and full string-to-sign reach application logs. Not returned to clients in production.
- **[live]** `/q/demo` and `/q/demo/pdf` stay publicly reachable with a database configured (`q/[token]/page.tsx:90-92`, `pdf/route.ts:34-36` reduce to `if (token !== 'demo') 404`). Fake data, but a live demo tenant on a production host.
- **[live]** `src/quote/issue.ts:149` mints a token unconditionally; on the `already_issued` branch the hash is never stored but `IssuedQuote.token` still carries it (`:193`). The route masks it today (`route.ts:74`); the next caller hands a customer a URL that 404s.
- **[latent]** `set search_path = public` rather than `''` on the three new SECURITY DEFINER functions (`0020:52`, `0022:180`, `0022:225`). Safe **today only because** every relation in their bodies is written `public.<name>`; nothing enforces that, and H5 is what it looks like when one is not.
- **[latent]** `0024:300-307` — `reject_candidate` omits the `status = 'unconfirmed'` guard `confirm_candidate` has (`:226-228`), so re-rejecting writes a duplicate verdict and double-weights the negative training signal.
- **[latent]** `0024:353-359` steers a `when others` handler by `sqlerrm not like '%already decided%'`. Safe now (Postgres puts constraint values in DETAIL, not MESSAGE) but it also hides genuine failures.
- **[latent]** `quote_versions.token_hash` has no format CHECK, though `0020:100` and `0021:297` both carry `check (… ~ '^[0-9a-f]{64}$')` for the same shape.
- **[latent]** EXECUTE is never revoked from PUBLIC on any new function. Consistent with `0006:112`, so not a regression, but it widens the blast radius of any future role.
- **[latent]** `platform_operators` insert/update are gated by `is_platform_operator()` itself (`0020:333-342`), so the operator tier is self-extending: one compromised operator session becomes permanent, self-renewing access to every prospect record.
- **[latent]** `src/storage/sigv4.ts:65,77` sort canonical headers and query with `localeCompare`; SigV4 requires ASCII byte order. The current fixed header set sorts identically under both, so this is a latent intermittent-403, not an auth bypass.
- **[latent]** `crawl.ts:715` fetches `robots.txt` without `chargeEnrichment`, so robots fetches are free and never count against `max_pages`.

## Checked and CLEAN

**The ZIP three-stage guard claim is true.** `src/parsing/zip.ts` bound 1 rejects declared per-entry (`:233`) and cumulative (`:240`) sizes before any inflate; bound 2 passes `maxOutputLength` to `inflateRawSync` (`:309`), catching an under-declaring bomb; bound 3 requires `inflated.length === uncompressedSize` (`:324`). Every offset read is bounds-checked first (`:193, :202, :248, :275, :289`); the EOCD scan validates candidates instead of trusting the first signature (`:145-158`); ZIP64 and encrypted entries are refused explicitly. **No path traversal is possible** — entry names never build a filesystem path; `read(name)` is an exact-name `Map` lookup and only literal constants (`xl/workbook.xml`, `word/document.xml`) are ever requested.

**XXE and entity expansion are absent by construction.** `src/parsing/xml.ts:92-96` steps over every `<!…>` construct as an opaque span, so DOCTYPE is never interpreted; `unescapeXml` (`:145-167`) resolves only the five predefined entities plus numeric refs. Billion-laughs and `SYSTEM "file:///etc/passwd"` have nothing to bind to, and there is no quadratic blowup in the scanner. **docx** reads only `word/document.xml`, never resolves or fetches relationship targets, and does not parse `w:instrText` — where `INCLUDETEXT`/`DDEAUTO` live.

**Storage path traversal.** Traced an attacker-controlled filename end to end: request body → `upload_jobs.filename` → `objectKey` (`jobs.ts:298`). The filename reaches the key only through `extensionOf` (`keys.ts:63-68`), a 12-entry allowlist falling back to `'bin'`. `agencyId`, `sha256` and `scope` are validated against anchored regexes or a closed Set. `assertSafeKey` (`:103-110`) rejects NUL, backslash, colon, newline and all non-ASCII; `local.ts:34-41` validates before `resolve` and re-checks prefix containment after.

**Upload caps are enforced against actual bytes, not client claims.** The per-chunk cap tests received length; `chunk_total` is derived server-side (the client never supplies it) and `record_upload_chunk` raises on `p_chunk_index >= v_total` (`0020:387-390`); replaying an index cannot inflate the total (PK + `on conflict do nothing`, and `received` is a `count(*)`); `assemble` fails the job when the assembled length or the digest disagrees (`jobs.ts:276-296`). "Declare 1 byte, send 10 GB" is not possible. Type allowlisting is by extension, not client MIME, and the surface is chosen by the handler rather than read from a request field.

**Quote tokens.** `randomBytes(32).toString('base64url')` (`issue.ts:75`) — CSPRNG, 256 bits. Only the SHA-256 is persisted; the lookup passes the hash, never the plaintext (`repository.ts:59`, `:146`). Unsalted SHA-256 is correct for a 256-bit uniform secret, and the non-constant-time SQL comparison leaks at most a prefix of a value the caller already holds. Never logged — there is no `console.*` anywhere in `src/storage`, `src/uploads`, `src/quote` or `src/db`. `robots: noindex` globally, `Referrer-Policy: strict-origin-when-cross-origin`, and `Cache-Control: private, no-store` on the PDF. Issuance is idempotent and does not rotate the stored hash.

**Tenant isolation on the new tables.** All thirteen new tables get both `enable` and `force row level security` (`0020:292-293, :325-326`, `0021:368-369`, `0024:154-155`) with policies keyed on `is_agency_member(agency_id)` or `is_platform_operator()` — no table is left unprotected, and the policy shape matches `0002:33-56` exactly. `is_platform_operator` (`0020:47-58`) takes **no parameter**, so it cannot be told which user to be, and resolves through `current_user_id()`, which is only ever set by `set_config(..., true)` inside a transaction in `withUser` (`db/client.ts:74` — the only such call in the repo): **a normal request cannot spoof it.** `issue_quote` is `security invoker` and does not trust its `p_agency_id` — the read is RLS-filtered and the insert must satisfy the WITH CHECK. `resolve_quote_link` touches neither `contacts` nor `event_briefs.contact_json`, and `calculation_trace.input` is a `PricingInput`, which has no personal fields, so invariant 2 holds; its only leak is H1. `erase_prospect` and `record_upload_chunk` derive the tenant from the row under RLS rather than taking it as a parameter. Every GRANT is `to app_user`, never `public`/`anon`.

**No id enumeration.** `confirm_candidate` reads its candidate under RLS (`0024:221`), so a cross-tenant id is indistinguishable from a missing one, and every route maps both to 404 (`uploads/[id]:28`, `chunks:66-69`, `candidates:71-73`, `inquiries/[id]/quote:39`). **SQL injection:** every query in the reviewed set is parameterised, including the identity `set_config`; the `format()` calls in the migrations are DDL over hardcoded arrays using `%I`.

**Prompt injection (A2) holds up.** `buildPrompt` (`src/agent/prompt.ts:252`) puts a 48-bit random nonce on every structural marker, escapes `&` before `<`, flattens control characters, and — the part that matters — counts markers in the finished prompt against the number authored (`hasForeignMarkers:208`) after multi-pass entity decoding. A whitelist over our own writes, decided in code, not a model self-report. Crawled and parsed text cannot reach a model at all today.

**Enrichment budget caps.** `charge_enrichment` (`0021:683-772`) locks the job then the budget in a fixed order, refuses on a missing lease, validates `p_micro_cents >= 0`, and tests prospect budget, run budget and page cap independently — so a caller passing `micro_cents = 0` still hits `max_pages`. `claim_enrichment_jobs` uses `for update skip locked` and increments `attempts` on claim. Only M6 is wrong here. **Purity gate:** locator length is capped at 200 chars (`purity.ts:145, :347`) before the regex scans, so the backtracking in `EMAIL`/`NAME_SHAPE` cannot become ReDoS; the primary defence is the closed enum vocabulary, and the gate runs on reads as well as writes. `cognee.ts` fetches only `COGNEE_URL` from env — no data-derived URL.

**`/api/health`** leaks nothing — 503 `unconfigured`/`degraded` with no driver text or hostname. **CSP** (`next.config.ts:27-36`) is self-only, `frame-ancestors 'self'`, `base-uri 'self'`, with `unsafe-eval` scoped to development.

## Could not determine without running

- Whether an upstream proxy caps request bodies in the real deployment (M1's severity turns on it; `output: 'standalone'` suggests self-hosted, where nothing does).
- Which role owns the SECURITY DEFINER functions — the migrations never name it, and both H5's impact and `resolve_quote_link`'s effective privileges depend on it.
- Whether `app_user` retains `CREATE` on schema `public` and `TEMP` on the database (H5's precondition).
- Whether the `candidate_verdicts` cascade in M7 bypasses RLS or errors — both are bugs, but which one needs a live database to see.
